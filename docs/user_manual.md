# 사용자 매뉴얼

설치와 실행은 [README](../README.md)를 먼저 보세요. 이 문서는 화면 사용법과 입력 파일 형식을 설명합니다.

> 이 도구는 포트폴리오용 참고 분석 도구입니다. 결과는 대출 승인·거절 결정이 아니며, 위험 신호는 부도확률이나 신용등급이 아닙니다.

## 1. 빠른 시연 (5분)

1. 앱 실행 후 **Home**에서 **시연 데이터 불러오기**를 누릅니다. 가상 기업 4곳이 등록되고 분석이 1건씩 만들어집니다.

   | 기업 | 시나리오 | 확인할 점 |
   |---|---|---|
   | 가상정밀(주) DEMO01 | 정상 | 위험 신호 없음 |
   | 가상유통(주) DEMO02 | 영업손실 지속 | HIGH 신호 3건, 유동성 MEDIUM |
   | 가상바이오(주) DEMO03 | 자본잠식 | 부분잠식 → 완전잠식, 부채비율 "해석불가" |
   | 가상건설(주) DEMO04 | 결함 데이터 | 단위 혼합·중복·재고 누락·연결/별도 혼입 경고 |

2. **위험 분석**에서 DEMO02를 골라 탐지된 신호와 근거를 봅니다.
3. **시나리오 분석**에서 고정비 비중 슬라이더를 올려 보세요. 영업손실 기업은 고정비가 있을 때 매출 감소의 영향이 커집니다.
4. **보고서**에서 PDF를 내려받습니다.
5. **분석 이력**에서 "재분석"을 누르면 같은 입력·같은 규칙의 결과가 완전히 같은지 확인할 수 있습니다.

처음부터 다시 시연하려면 앱을 끈 뒤 `data/cif.db` 파일과 `data/raw/` 폴더를 지우고 다시 실행합니다 (분석 이력이 모두 사라집니다).

## 2. 입력 파일 형식

CSV(UTF-8 또는 CP949) 또는 XLSX, **한 파일에 한 기업**, 한 행에 한 계정. 양식: [`data/samples/template.csv`](../data/samples/template.csv)

| 컬럼 | 설명 | 예 |
|---|---|---|
| `company_code` | 기업코드. 기업 관리에서 등록한 코드와 같아야 함 | `MYCO01` |
| `fiscal_year` | 결산연도. 결산일이 속한 연도 | `2025` |
| `fiscal_end_date` | 결산일 (`2025-12-31`, `2025.12.31`, `2025/12/31`) | `2025-12-31` |
| `statement_scope` | 연결 `CFS`(또는 `연결`) / 별도 `OFS`(또는 `별도`) | `CFS` |
| `account_name` | 계정명. 아래 표의 이름 또는 동의어, 띄어쓰기 무시 | `영업이익(손실)` |
| `amount` | 금액. 쉼표·괄호 음수 `(50)` 허용. 비용은 양수로 입력 | `"1,234"` |
| `unit` | `원`, `천원`, `백만원` (행마다 달라도 됨) | `백만원` |

인식하는 계정 (동의어 전체: [`config/account_map.yaml`](../config/account_map.yaml)):

| 계정 | 쓰임 |
|---|---|
| 자산총계, 유동자산, 재고자산, 부채총계, 유동부채, 자본총계, 자본금 | 유동성·안정성 비율, 자본잠식 |
| 매출액, 영업이익, 당기순이익, 이자비용 | 수익성 비율, 이자보상배율 |
| 영업활동현금흐름 | 현금흐름 비율, 현금흐름 적자 |
| 차입금 | 금리 스트레스 테스트 (없으면 금리 시나리오만 계산 불가) |

매핑되지 않은 계정은 분석에서 빠지고 경고로 표시됩니다. 3개년 자료를 권장합니다 (1~2개년이면 추세·연속 규칙이 제한됩니다).

## 3. 화면별 사용법

### Home
등록 기업·심사 건·분석 수, 최근 분석 10건, 심사 건별 최신 분석의 위험 신호를 보여 줍니다.

### 기업 관리
- **기업 등록**: 기업코드(파일과 같아야 함), 기업명, 업종.
- **심사 건 등록**: 기업을 고르고 심사 건 번호와 목적을 입력합니다.
- **재무자료 업로드**: 기업을 고르고 파일을 올린 뒤 **업로드 및 검증**. 원본은 `data/raw/`에 해시 이름으로 보관되고, 검증을 통과하면 정제 결과가 저장됩니다. 기업코드가 다른 파일은 저장하지 않습니다.
- **분석 실행**: 심사 건과 자료를 고르고 **분석 실행**. 결과는 새 분석으로 저장됩니다. **AI 해석 사용**은 API 키가 설정된 경우에만 켤 수 있으며 1~2분 걸립니다.

### 데이터 검증
자료를 고르면 원본을 다시 검증해 보여 줍니다.
- **오류·경고**: 수준(ERROR는 분석 불가, WARNING·INFO는 분석 가능), 원본 행 번호, 연도, 계정.
- **단위·계정과목**: 단위별 행 수와 원본 계정명 → 표준 계정 매핑.
- **정제 결과**: 원 단위로 환산한 연도별 금액. **원본**: 올린 파일 그대로.

주요 코드: `MISSING_REQUIRED` 필수 계정 누락 · `DUPLICATE_SAME` 같은 값 중복(1건 사용) · `DUPLICATE_CONFLICT` 다른 값 중복(오류) · `SCOPE_MIXED` 연결/별도 혼합(우선 범위만 사용) · `BALANCE_MISMATCH` 자산 ≠ 부채+자본 · `FISCAL_MONTH_CHANGED` 결산월 변경 · `EQUITY_ROLLFORWARD_GAP` 자본 변동이 당기순이익과 1% 넘게 다름(배당·증자 등 확인, 보고서에 자본변동표 요청) · `UNMAPPED_ACCOUNT` 인식하지 못한 계정.

### 재무 분석
연도별 비율 10종과 추세 그래프. 값 대신 상태가 보이면 계산하지 않은 것입니다: `DIV_BY_ZERO`(분모 0), `NOT_MEANINGFUL`(자본 0 이하 등 해석 불가), `MISSING_INPUT`(계정 누락), `NO_INTEREST_EXPENSE`(이자비용 0). **계산식과 사용 계정**에서 각 값의 입력 금액을 확인할 수 있습니다.

### 위험 분석
규칙을 **탐지된 위험 신호 / 판단하지 못한 규칙 / 해당 없음**으로 나눠 보여 줍니다. 자료가 없어 판단하지 못한 것은 "위험 없음"이 아니라 "판단 불가"로 표시됩니다. 적용한 기준값은 화면 아래에서 확인할 수 있습니다.

### 시나리오 분석
매출 변화, 영업이익률 변화, 금리 변화와 가정(변동금리 비중, 적용 개월, 고정비 비중)을 슬라이더로 바꿔 설정 파일의 기본 시나리오와 함께 계산합니다. **여기서 바꾼 값은 저장되지 않습니다.** 저장된 분석은 설정 파일의 기본 가정을 씁니다.

### 보고서
분석을 고르면 10개 섹션 보고서를 보여 주고 HTML·PDF로 내려받을 수 있습니다. 화면 위의 지표는 해석 방식(AI/규칙 기반)과 검증된 문장 수입니다. 검증되지 않은 AI 문장은 보고서에서 별도 목록으로 표시되며 사실로 쓰지 않습니다.

### 분석 이력
심사 건의 모든 분석 실행을 보여 줍니다 (수정·삭제 불가). **재분석**은 같은 자료를 현재 규칙으로 다시 분석해 새 실행을 추가합니다. 두 실행을 고르면 입력·설정 변경 여부, 비율 변화, 위험 신호 변화를 비교합니다.

## 4. AI 해석 설정

1. https://platform.claude.com 에서 API 키를 만듭니다 (사용량에 따라 비용 발생).
2. `pip install -e ".[dev,llm]"`로 AI 패키지를 설치합니다.
3. **앱을 실행할 같은 터미널**에서 키를 설정하고 앱을 실행합니다.

   ```bash
   $env:ANTHROPIC_API_KEY = "본인의 API 키"
   ```

   ```bash
   .\.venv\Scripts\python.exe -m streamlit run app/Home.py
   ```

4. 기업 관리 → 분석 실행에서 **AI 해석 사용**을 켭니다.

키는 코드·DB·로그·보고서에 저장되지 않습니다. AI 호출이 실패하면(인증·시간 초과·거절·형식 오류) 규칙 기반 문장으로 보고서를 만들고 보고서 10번 섹션에 실패 사유를 남깁니다.

## 5. 보고서 내보내기

심사 건별 최신 분석을 HTML·PDF로 저장합니다.

```bash
.\.venv\Scripts\python.exe -m cif.export --out "C:\Users\<사용자>\Desktop\CIF_여신심사_보고서"
```

`--import-ai <보고서 JSON>`을 붙이면 예전에 받은 AI 응답을 API 재호출 없이 새 분석으로 다시 사용합니다. 같은 기업·같은 입력 파일로 분석한 이력이 DB에 있어야 하며, 모델명에 "(저장된 응답 재사용)"이 표시됩니다.

## 6. 문제 해결

| 증상 | 해결 |
|---|---|
| AI 해석 체크박스가 비활성 | 앱을 실행한 터미널에 `ANTHROPIC_API_KEY`가 없음. 키 설정 후 같은 터미널에서 다시 실행 |
| 업로드 시 `COMPANY_MISMATCH` | 파일의 `company_code`와 선택한 기업코드가 다름 |
| PDF 내려받기 대신 경고 | 한글 글꼴(맑은 고딕·나눔고딕)을 찾지 못함. HTML로 내려받기 |
| 분석 실행 시 "검증 오류" | 데이터 검증 화면에서 ERROR 행을 고친 파일을 다시 업로드 |
| 코드 수정이 화면에 반영 안 됨 | 앱을 종료(Ctrl+C) 후 다시 실행 (`src/cif` 패키지는 자동 새로고침 대상이 아님) |
