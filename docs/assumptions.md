# 계산식과 가정

모든 수치는 코드(`src/cif/analysis/`)가 계산하며, 기준값은 `config/*.yaml`에서 바꿀 수 있습니다.
설정 파일이 바뀌면 해시가 달라져 분석 이력에 기록되고, 분석 이력 화면에서 비교됩니다.

## 1. 데이터 처리

| 항목 | 규칙 |
|---|---|
| 금액 저장 | 원 단위 정수. 단위 환산은 소수 오차가 없는 Decimal로 계산, 원 미만은 사사오입 후 경고 |
| 결산연도 | 결산일이 속한 연도. `fiscal_year`와 결산일 연도가 다르면 오류 |
| 연결/별도 | 한 분석에는 한 범위만 사용. `settings.yaml`의 `scope_priority`(기본 CFS → OFS) 순서로 선택하고 나머지 행은 제외 |
| 중복 | 같은 연도·계정에 같은 금액이면 1건 사용(경고), 다른 금액이면 오류(둘 다 사용하지 않음). 동의어로 같은 계정이 두 번 들어온 경우도 포함 |
| 정합성 | 자산총계와 부채총계+자본총계 차이가 자산의 0.1%(`balance_tolerance`)를 넘으면 경고 |
| 자본 변동 | (당기 자본 − 전기 자본) − 당기순이익의 차이가 max(\|전기 자본\|, \|당기순이익\|)의 1%(`equity_rollforward_tolerance`)를 넘으면 경고. 배당·증자·기타포괄손익으로 정상적으로도 생기므로 위험 신호가 아니라 **자본변동표 요청**으로 보고서에 표시 |
| 오류 처리 | ERROR가 하나라도 있으면 분석하지 않음 (일부 데이터만으로 조용히 분석하지 않기 위해) |

## 2. 재무비율

상태가 `OK`일 때만 값이 있으며, 그 외에는 값을 비우고 이유를 표시합니다.

| 지표 | 계산식 | 단위 | 예외 |
|---|---|---|---|
| 유동비율 | 유동자산 / 유동부채 × 100 | % | 분모 0 → DIV_BY_ZERO |
| 당좌비율 | (유동자산 − 재고자산) / 유동부채 × 100 | % | 재고자산 없으면 MISSING_INPUT (0으로 가정하지 않음) |
| 부채비율 | 부채총계 / 자본총계 × 100 | % | 자본 ≤ 0 → NOT_MEANINGFUL |
| 자기자본비율 | 자본총계 / 자산총계 × 100 | % | 음수 자본도 계산 |
| 영업이익률 | 영업이익 / 매출액 × 100 | % | 매출 0 → DIV_BY_ZERO |
| ROA | 당기순이익 / 평균자산총계 × 100 | % | 전기 자료 없으면 기말잔액 사용 (기준 표시) |
| ROE | 당기순이익 / 평균자본총계 × 100 | % | 당기 또는 전기 자본 ≤ 0 → NOT_MEANINGFUL |
| 총자산회전율 | 매출액 / 평균자산총계 | 회 | ROA와 같음 |
| 이자보상배율 | 영업이익 / 이자비용 | 배 | 이자비용 0 → NO_INTEREST_EXPENSE (위험 아님), 영업손실이면 음수로 계산 |
| 영업현금흐름 비율 | 영업활동현금흐름 / 유동부채 × 100 | % | 분모 0 → DIV_BY_ZERO |

- 평균잔액 = (전기말 + 당기말) / 2. 첫해는 기말잔액이라 다음 해 값과 기준이 다릅니다.
- 이자비용은 금융비용 전체가 아닌 **이자비용 계정**만 사용합니다.
- 분모가 음수이면 NOT_MEANINGFUL입니다.

## 3. 위험 규칙 (`config/risk_rules.yaml`, 버전 1.0.0)

업종을 구분하지 않은 일반 가정값입니다. 업종 벤치마크와 비교하지 않습니다. 기준 연도는 최근년도입니다.

| 규칙 | 조건 | 심각도 |
|---|---|---|
| 완전자본잠식 | 자본총계 ≤ 0 | HIGH |
| 부분자본잠식 | 0 < 자본총계 < 자본금 (완전잠식이면 중복 표시 안 함) | MEDIUM |
| 영업손실 지속 | 최근 2개년 연속 영업이익 < 0 (2개년 자료 없으면 판단 불가) | HIGH |
| 이자보상배율 악화 | 1.0배 미만 또는 전년 대비 2.0배 이상 하락 | HIGH |
| 유동성 악화 | 유동비율 100% 미만 또는 전년 대비 20%p 이상 하락 | MEDIUM |
| 영업현금흐름 적자 | 영업활동현금흐름 < 0, 2개년 연속이면 HIGH로 상향(코드 고정) | MEDIUM/HIGH |
| 자료 불일치·누락 | 정합성 불일치, 부분>합계, 필수 계정 누락, 음수 이상치, 범위 연도 누락, 결산월 변경 | MEDIUM |

모든 규칙은 **신호 발생 / 해당 없음 / 판단 불가** 중 하나로 평가합니다. 자료가 없으면 "해당 없음"이 아니라 "판단 불가"입니다.

### 위험 신호 원인 진단 (보고서 9-1, 9-2)

| 항목 | 방법 |
|---|---|
| 산업 공통 / 기업 고유 | DB에 **같은 업종**으로 등록된 다른 기업(최신 자료, 같은 재무제표 범위)에 같은 규칙을 같은 연도로 적용. 신호가 나온 비율이 `diagnosis.peer_common_share`(기본 0.5) 이상이면 산업 공통, 미만이면 기업 고유, 비교 가능 기업이 `min_peers`(기본 1) 미만이면 판단 불가 |
| 영업현금흐름 적자 | 영업현금흐름 = 당기순이익 + 조정 + 영업 자산·부채 변동 + 기타(이자·법인세 등). 가장 큰 감소 요인과 재무활동 조달액 표시. 세부 항목이 없으면 순이익과의 차이만 표시 |
| 영업손실 지속 | 영업이익 변화 = 매출 효과(매출 변화 × 기초 이익률) + 이익률 효과(기말 매출 × 이익률 변화) — 정확히 성립 |
| 이자보상배율·유동성 | 전년 대비 영업이익·이자비용, 유동자산·유동부채 증감 |
| 자본잠식 | 기간 누적 당기순이익 |
| 개선 계획·확인 과제 | `risk_rules.yaml`의 규칙별 `remediation`·`checks`·`monitoring` 템플릿 (규칙 기반 제안이며 사실 판단 아님) |

자료로 확정할 수 없는 부분(예: 운전자본 변동의 세부 구성)은 "추가 확인 필요"로 표시하고 단정하지 않습니다.
비교 기업 수가 적으면(예: 2곳) 판단의 통계적 근거가 약하므로 보고서에 비교 기업 이름과 결과를 함께 표시합니다.

## 4. 스트레스 테스트 (`config/stress_scenarios.yaml`)

최근년도 실적에 시나리오를 적용하고 기본(BASE)과의 차이를 계산합니다. 적용 순서는 고정입니다.

1. **매출 변화**: 영업비용(매출 − 영업이익)을 고정비(× 고정비 비중)와 변동비(매출 비례)로 나눠 다시 계산
   `변화 후 영업이익 = 변화 매출 − 고정비 − 변동비율 × 변화 매출`
2. **영업이익률 변화**: 변화된 매출 × 변화폭(%p)을 더함
3. **이자비용 변화**: `차입금 × 변동금리 비중 × 금리 변화(bp)/10,000 × 적용개월/12`

| 가정 | 기본값 | 의미 |
|---|---|---|
| 변동금리 비중 | 0.5 | 차입금 중 금리 변화가 반영되는 비율 |
| 적용 개월 | 12 | 연중 금리 변화가 적용되는 기간 |
| 차입금 잔액 | 기말 잔액이 연중 일정 | 상환·신규 차입 반영 안 함 |
| 고정비 비중 | 0.0 | 업종·기업마다 달라 기본값은 0(비용 전부 변동비) |

- 고정비 비중이 0이면 영업손실 기업의 매출 감소가 **손실 축소**로 계산됩니다. 결과에 경고가 붙으며, 시나리오 분석 화면에서 비중을 조절해 보는 것을 권합니다.
- 금리 인하로 이자비용이 음수가 되면 0으로 제한합니다.
- 이자비용 자료가 없으면 금리 시나리오만 계산하지 않고, 매출·이익률 시나리오는 계산합니다 (이자비용·이자보상배율 칸은 비움).
- 보고서 금액 단위는 금액 크기에 따라 자동으로 고릅니다: 10조원 이상이면 조원, 아니면 억원.
- 법인세 효과는 반영하지 않습니다 (세전 영향만).

## 5. AI 해석과 문장 검증

- AI(Claude, 기본 `claude-opus-5-5`)는 **근거 패키지**만 받습니다: 계정 금액, 비율(상태 포함), 위험 규칙 결과와 기준값, 시나리오 결과·변수, 검증 이슈. 각 항목에는 ID가 있습니다 (예: `ratio:ROA:2025`).
- 응답은 JSON 스키마로 강제하고 Pydantic으로 다시 검증합니다. 스키마에 없는 필드(예: 승인 여부)가 있으면 응답 전체를 거부합니다.
- 문장마다 검증 상태를 붙입니다.

| 상태 | 조건 | 보고서 표시 |
|---|---|---|
| 확인됨 | 인용 근거가 있고 본문 숫자가 인용 근거 값, 두 근거의 차이·증감률, 또는 근거 설명문의 숫자와 표시 정밀도 안에서 일치 | 본문 |
| 근거 없음 | 인용이 없거나 존재하지 않는 근거 | "검증되지 않은 문장" 목록 |
| 수치 불일치 | 숫자가 인용 근거와 맞지 않음 | "검증되지 않은 문장" 목록 |
| 정책 위반 | 대출 승인·거절·가결·부결을 결정·권고하는 표현 | 본문을 싣지 않음 |

- 원·백만원·억원 환산, 음수(크기 비교), "2024~2025년" 같은 연도 범위, 개수(건·개년)를 처리합니다.
- 실제 응답 확인 결과 (DEMO02, 45문장): 확인됨 44, 수치 불일치 1 (인용하지 않은 연도의 값을 쓴 경우).

## 6. 재현성

분석마다 입력 파일 SHA-256, 설정 파일 4개의 SHA-256, 앱 버전, 규칙·시나리오·프롬프트 버전, AI 모델명을 기록합니다.
재분석은 보관된 원본 사본을 다시 검증해서 계산하므로, 같은 입력·같은 설정이면 결과가 같습니다 (테스트로 확인).
AI 문장은 모델 응답에 따라 달라질 수 있으며, 이 경우에도 수치·표·위험 신호는 같습니다.

## 7. 알려진 한계

- 업종별 기준, 외부 신용정보, 담보, 비재무 정보(경영진·산업 전망)를 반영하지 않습니다.
- 재무제표 세부 계정(현금성자산, 매출채권, 차입금 만기)이 없어 단기 지급능력 판단이 제한됩니다.
- 자본 변동은 순이익과의 차이만 확인합니다. 배당·증자·기타포괄손익 금액을 입력받지 않으므로 차이의 원인은 자본변동표로 확인해야 합니다.
- 검증기는 숫자 일치만 확인합니다. 문장의 해석이 타당한지(예: 인과 관계)는 사람이 판단해야 합니다.
- 단위 없는 숫자는 인용한 모든 근거와 비교하므로 다소 관대합니다.
- 시연 데이터는 가상 기업이며 실제 산업 수치를 반영하지 않습니다.
- **금융 부문을 연결하는 기업**(예: 할부금융 자회사가 있는 자동차 제조사)은 할부·리스 채권 증가가 영업활동현금흐름에 잡혀 연결 기준 영업현금흐름이 적자로 보일 수 있습니다. 업종 무관 규칙은 이를 위험 신호로 표시하므로, 부문별(제조/금융) 현금흐름을 따로 확인해야 합니다. 실제 현대자동차 2023~2024년 자료에서 이 경우가 나타났습니다.
